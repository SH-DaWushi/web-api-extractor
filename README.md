**简体中文** | [English](README.en.md)

**把「只能手动点网页的系统」，变成 AI 能直接调用的工具 —— 你不用写一行代码。**

---

## 这是什么

很多系统只有网页界面，没有 API。你想让 AI 助手帮你查数据、提工单、导报表，
却卡在「它碰不到这个系统」这一步。

scry-mcp-gen 的做法很直接：

> **你在浏览器里怎么点，它就记下来，然后把这些操作变成 AI 可以调用的工具。**

你不用看接口文档，不用写代码，也不用理解任何技术名词。

---

## 谁适合用

- 手上有一套**只能登录网页、手动点操作**的系统（OA、ERP、CRM、工单、报表、
  内部管理后台……）
- 想让 AI 助手替你完成里面的重复操作
- 没有 API 文档，也没有开发资源

**你需要准备：**

- 一个支持「技能 / Skill」的 AI 助手桌面客户端
- 你自己的电脑（所有数据都留在本机）
- **Windows**（唯一受支持的平台；macOS / Linux **不受支持**、也未做验证 —— 凭据加密依赖 Windows 的 DPAPI，且抓包与交互式登录必须弹出真实桌面浏览器窗口）
- 对该系统的**合法授权** —— 只对你自己有权使用的系统使用

## 两步就能用起来

### 第一步 · 把技能装进你的 AI 助手

两种装法，选一种 —— **你不需要安装任何库，也不需要运行任何命令**：

- **拖进技能设置页** —— 把技能文件夹（或 `scry-mcp-gen-agent.zip` 导入包）拖进
  AI 助手的 **「技能 / Skill」** 设置页。不同客户端的入口位置不一样，但都在技能设置里。
- **拖进对话让 Agent 装** —— 直接把技能文件夹（或 zip）拖进对话，跟 AI 说
  「帮我把这个技能装上」即可。

> zip 从哪来？在 [Releases 页面](https://github.com/SH-DaWushi/web-api-extractor/releases/latest)
> 下载 `scry-mcp-gen-agent.zip` —— 它就是技能文件夹本身打成的包，内容一模一样，
> 只是不用自己去拉整个仓库。

装好后，技能列表里会出现 **scry-mcp-gen** 这一项。你的 AI 助手从此多了一项能力：
**陪你在浏览器里完成登录、记录你的操作、并把它们做成工具。**

> 首次使用要装一点运行环境（含一个浏览器内核），**这些都由 AI 自己完成**，你不用管。
> 如果你确实想自己动手（或要装给同事），环境准备与启动命令见
> [技术文档的「安装形态」与「启动服务」](https://github.com/SH-DaWushi/web-api-extractor/blob/main/docs/reference.md)。

### 第二步 · 用对话告诉它你要什么

这一步不用记任何命令，像平常聊天一样：

```
你：帮我给我们的 OA 系统做一套 MCP 工具
AI：（打开浏览器）请在弹出的窗口里完成登录，然后告诉我
你：登录好了
AI：登录态已保存。现在请你在浏览器里，把你想变成工具的功能都操作一遍
    —— 比如查列表、点开详情、提交一张单子
你：（操作完）好了
AI：收到，抓到 23 个接口。其中登录接口用了密码加密，我先核实一下再生成
    ……
    生成完成，包含这些工具：
      · 查我的待办        · 查工单详情
      · 提交工单          · 导出报表
    以后你（或任何接上它的 AI）就能直接调用它们了
```

**整个过程你只需要做两件事：在浏览器里登录，然后正常点一遍你要的功能。**

## 你会得到什么

一套**可以长期使用、随时能加功能**的工具集：

| 你得到的 | 意味着 |
|---|---|
| AI 能直接操作那个系统 | 不用再手动点网页 |
| 登录态可复用 | 抓包与后续调用都能带登录态，不必每次重新登录 |
| 自动续期（有条件） | 识别到账号密码登录接口、且请求确实构造得出来时，生成的项目支持 token 过期自动重登录；验证码 / 短信 / 单点登录这类站点**过期要重新登录一次**（生成的项目会自己弹出浏览器窗口让你登录，不必找 Agent 重来一遍） |
| 后续想加功能，再操作一遍就行 | 不用推倒重做 |
| 可以把分发包给同事 | 对方只能调用，无法改动你的工具 |

## 它能做什么 / 它做不到什么

> 这里是给你判断「能不能用」的概览；每条判定规则与代码依据见技术文档的
> 「能力边界（做不到什么）」与「平台矩阵」。

### 能做到

1. **把网页系统变成 AI 的工具集** —— 你在浏览器里正常点一遍，后台记录全部请求与响应。
2. **自动整理接口** —— 同构接口自动合并（`/user/123`、`/user/456` → `/user/{id}`），
   参数按真实样本推导出类型；**能安全沿用的取值会直接变成默认值**（抓包时带了什么就用什么），
   于是你和 AI 都不必再猜「这个参数要填什么」。**取值会改变返回内容的参数例外**（例如设备接口的
   `count=yes`：那样只返回一个计数、不返回真正的列表）—— 这类参数不会被写死：**真测到它会改变
   返回内容的**（抓包里两种取值都出现过），服务会要求明确指定，免得 AI 拿到不完整的数据；**只是
   名字听起来像开关的**（`page` / `sort` / `format` … ），服务不写死、也不强求 —— 你不填时它
   就不会把这个参数发出去，服务端用自己的默认值，拿回来的东西看着不完整再换个值调一次即可。
   分享给别人之前，服务会把**哪些参数沿用了
   抓包取值**如实列出来（只列参数名，供你检查），不会闷声把抓包数据发出去。
3. **两种登录都覆盖** —— 能构造请求的走表单登录；验证码 / 短信 / 单点登录走真实浏览器
   交互式登录（**登录是否完成由你确认** —— 这是流程约定，服务端只能记录并提示，不会替你判定）。
   到底属于哪种，由**实测**决定：会真的试着发一次登录请求，然后把结论记下来 —— 所以**生成的
   项目也自带这种能力**：验证码站点过期时，它会弹出浏览器窗口让你登录一次（`login_interactive()`），
   而不是假装能自动重登录（那样只会让你以为配好了）。
   登录本身需要的额外参数（例如登录页先要取一个一次性令牌）若能从**公开接口**自动取到，
   生成的服务会在登录前自己去取，**不用你填**；取不到时会明确报错并提示重新抓包。
4. **生成可直接运行的 MCP 项目** —— 多域名路由、类型化参数、鉴权**按每个接口实测的方式**
   各自发送（同一台服务器上有的接口用 Authorization、有的只认 Cookie，也不用你操心）、
   写操作需 `confirm=true` 且会在 README 里单列「会改数据的工具」清单、自带冒烟测试与只读诊断。
5. **凭据加密保存、重启自动恢复、401 自动重登录** —— 前提是识别到了账号密码登录接口、
   请求确实构造得出来，且系统是 Windows；验证码 / 单点登录这类站点改为**一键重新登录**
   （弹出浏览器窗口，你本人登录一次），不会假装能自动续期。
6. **增量迭代** —— 再抓一轮 → 看差异 → 合并 → 重出代码，不用推倒重做；这一轮没抓到的接口
   只标记「本轮未见」，**永不自动删除**。
7. **记录时即脱敏** —— 请求侧的凭据当场抹掉：JSON / 表单体里「像凭据的字段名」值一律抹掉
   （含 `pass` / `pin` / `otp` / `api_key` 等同义词，表单里的无值控制项也不会漏），带 token 的
   请求头同样遮蔽；只保留长度与形态，便于判断「这是不是密文」。
8. **可导出「用户态分发包」** —— 给同事的那份只能调用与只读诊断，改不了工具集。

### 做不到

| 做不到 | 说明 |
|---|---|
| **上传文件** | 文件上传的请求体既不提取参数、也不脱敏；附件内容不会被分析 |
| **实时推送** | WebSocket 的连接与帧内容**都会记录进抓包**（凭据同样脱敏），但**不会**变成工具；流式响应也无专门处理 |
| **文件下载（自动落盘 / 流式）** | 业务文件下载（CSV / PDF / XLSX / ZIP 等）会识别并生成 `[FILE]` 工具，工具把响应体原样返回（文本在 `text`、二进制在 `base64`），落盘由调用方自己做；不支持的是**自动 / 流式写入磁盘** |
| **GraphQL** | 当普通接口处理，不展开查询语义 |
| **二进制接口** | protobuf 之类的响应不解码，拿不到结构化字段 |
| **大接口的响应结构** | 响应超过 256 KB 会被整条丢弃（不是截断），因此拿不到响应结构。这不是死路：抓包时可以让 Agent 把上限调大（最多 64 MB）再抓一次 |
| **验证码 / 密码加密类站点的自动续期** | 这类站点的登录过不去验证码，**没有自动重登录**，过期要重新登录一次。生成的项目自带这件事：`login_interactive()` 会弹出真实浏览器窗口让你自己登录，确认后即保存（**不会**自动判定"你登录好了"） |
| **没有桌面的机器** | 抓包与登录必须弹出真实浏览器窗口 |

### 有条件的

- **只有你操作过的功能才会出现** —— 没点过的接口不会被猜到。
- **登录态文件里 Cookie 仍是明文，账号密码则用系统级 DPAPI 加密**（仅同一台机器上的同一个
  Windows 用户可解；DPAPI 不可用时宁可不保存也不写明文）—— 该文件只该留在你自己的电脑上，
  不要提交、同步、截图或分享（复制到别处时 Cookie 仍可读，密码读不出）。
- **生成的工具里凭据同样是加密保存的，而且只认本机的你** —— 换成另一台电脑、或换一个
  Windows 登录用户，加密凭据就解不开了。出路很简单：**删掉项目里的 `cred_cache.bin`，再登录
  一次**（服务会先弹窗问你一次账号密码；它也会在状态与报错里直接告诉你这句话）。把生成的工具
  分享给同事时，**凭据不随包走**，让对方自己登录一次即可。
- **记录不会自动清理** —— 抓包记录只追加、没有自动轮转，长会话会持续变大。
- **不提供验证码 / 登录加密的逆向或绕过** —— 遇到就走交互式授权。

## 常见问题

| 问题 | 回答 |
|---|---|
| 我需要会编程吗？ | 不需要。全程对话 + 在浏览器里操作。 |
| 我的账号密码安全吗？ | **登录态文件里 Cookie 是明文的，账号密码则加密保存**（本机 `auth_states/` 目录下的 json；`http_login` 用 Windows DPAPI 加密后存进 `secrets_enc` 字段，仅同一台机器上的同一个 Windows 用户可解密，DPAPI 不可用时宁可不保存也不写明文；旧版遗留文件在被读取前可能仍是明文），所以它只能留在你自己的电脑上，**不要提交、同步、截图或分享**。抓包时脱敏的是**请求侧**：JSON / 表单体里「像凭据的字段名」值抹成 `***`（含 `password` / `pass` / `pin` / `otp` / `token` / `api_key` 等同义词，表单里的无值控制项也不会漏），`Authorization` 与带 token 的请求头也整段遮蔽；但 **URL 与响应体不脱敏**，`multipart` / XML / 纯文本等非 JSON、非表单的请求体同样不脱敏。生成的项目里凭据是加密保存的（仅 Windows）。完整说明见技术文档「安全设计」（见文末[深入了解](#深入了解)）。 |
| 数据会上传到云端吗？ | 不会。所有记录都在你电脑的数据目录里（`~/.scry`）。 |
| 支持哪些系统？ | 只要你能用浏览器登录并操作，就能做 —— 包括需要验证码、短信验证、单点登录的内部系统（这类站点走交互式授权，**登录态过期要重新登录一次**，不会自动续期；生成的项目会自己弹出浏览器窗口让你登录一次）。 |
| 能做多复杂的功能？ | 取决于你在浏览器里点过什么。上传文件、GraphQL、二进制接口这几类不做；WebSocket 的帧内容会被记录进抓包，但也不会变成工具 —— 见上文「它做不到什么」。 |
| 生成的工具只能我自己用吗？ | 也可以把分发包给同事；拿到的人只能调用，不能修改工具集。 |
| 系统改版了怎么办？ | 再操作一遍，让 AI 补上变化的部分，不用重做。 |
| 数据会一直变大吗？ | 会。抓包记录只追加、不会自动清理，长会话需自行清理数据目录。 |
| 非 Windows 能用吗？ | **不支持。** 本项目只支持 Windows：凭据加密依赖 Windows 的 DPAPI，且抓包与交互式登录必须弹出真实桌面浏览器窗口；macOS / Linux 既未支持也未验证。见技术文档「平台矩阵」。 |
| 这是 Skill 还是 MCP？ | 你不用区分。它底层是一个 MCP 服务，上层是 Agent 可调用的技能 —— 导入技能就能用。 |
